# How code is written here

`AGENTS.md` is the law and short; this is the detail. The same text is read by humans, Claude Code and Codex,
so everything is written to be followed literally.

## Workspace

```
Cargo.toml                 workspace; members = crates/*, xtask
rust-toolchain.toml        the one Rust version
crates/firecal-types/
crates/firecal-ingest/
crates/firecal-harmonize/
crates/firecal-query/
crates/firecal-wasm/
xtask/                     check, parity, build-wasm, serve: no shell scripts
web/map/  web/calendar/    TypeScript packages
docs/  pitch/
```

**No shell scripts.** Windows and macOS share one entry point: `cargo xtask <task>`. Line endings are LF
(`.gitattributes`); paths go through `std::path`, never string concatenation.

## Rust

**Shape**
- A crate is a few modules; a module is one idea; a file is about 200 lines. `lib.rs` only declares modules and
  re-exports the public API.
- `//!` at the top of every module says what it is in a sentence. `///` on every public item. No comment
  repeats the code; the reason for a choice goes in `docs/` or the commit.
- Tests live beside the module in `tests.rs`. Fixtures in `tests/fixtures/`.

**Names**
- Say what the thing does: `aggregate_month`, not `process`. Units in the name when a number has one:
  `frp_megawatts`, `sigma_counts`.
- Newtypes for things that must not be mixed: `MonthIndex(u16)`, `CellIndex(u32)`. Never a bare integer that
  could be either.

**Types and errors**
- Make invalid states unrepresentable: an enum, not a string or a flag.
- An `enum Error` where a caller decides what to do with it; a `String` only at the edge, where it is printed.
- No `unwrap` or `expect` outside tests. No `panic!` in library code. No indexing that can go out of range
  without a check the compiler or a test proves.
- `#![forbid(unsafe_code)]` in every crate except `firecal-wasm`, where `unsafe` is only the buffer boundary
  and each block says why it is sound.

**What the libraries may do** (`types`, `query`, and the pure parts of `ingest` and `harmonize`)
- Take slices, return slices or write into a `&mut` the caller owns. No files, no clock, no network, no
  threads, no global state. The binaries at the edge do the I/O.
- **No dependencies.** Parse CSV, dates and bytes by hand. An addition is asked for, with a reason.
- **Deterministic, so wasm equals native.** Output must not depend on hash order (use `BTreeMap` or sorted
  `Vec`), on thread count, or on the platform. For floating point: use `f64` and `+ - * /` and `sqrt`, which
  are exactly rounded everywhere. **Do not call `exp`, `ln`, `powf`, `sin`, `cos`**: native and wasm use
  different math libraries and can differ in the last bit. If one is needed, write it with only those
  operations, and test it. Sums are done in a fixed order.
- Throughput work (parallel parse in `ingest`) uses `std::thread::scope`. That is allowed only in the
  binaries and in `ingest`, never in `query` or `types`.

**Green before a PR**
```
cargo xtask check      # fmt --check, clippy pedantic -D warnings, test --workspace
cargo xtask parity     # when you touched types, query or wasm
```

## Tests

The team cannot review Rust line by line, so **the tests are the review**.

1. Every function that computes has a test; the test says what is expected, in numbers you can check by hand.
2. Fixtures are tiny and hand-counted: ten hotspots, one tile, three years. A fixture's expected output is
   written down by a person, not generated by the code under test.
3. Bug first as a failing test, then the fix.
4. Harmonization has a **property test**: over the overlap years, harmonized VIIRS must match MODIS monthly
   totals within a tolerance written in the test with the reason for the number.
5. A change that must not change output is proven by running old and new on the same input and comparing the
   bytes.
6. Real FIRMS data is never a fixture and never committed.

## TypeScript (web)

- **Plain TypeScript, strict.** `"strict": true`, no `any`, no `as` casts that hide a hole. Browser APIs and
  modules, no UI framework.
- **Allowed dependencies:** `typescript`, `vite`, `maplibre-gl`, one drawing plugin for it. Charts and the
  calendar are drawn by hand on Canvas or SVG. Anything else is asked for.
- **The UI computes nothing about fire.** Every count, median, anomaly, sigma and analog comes from the core
  through `wasm/firecal.d.ts`. The UI picks, draws and formats.
- **State is one object** and one function that renders it. Events change the state; render reads it.
  A new person should be able to find where a number on screen comes from in one step.
- A file is a component or a helper, about 200 lines. Names say what a thing does.
- **Accessible:** the ramp is colorblind-safe and also readable in grayscale; every cell has a text value on
  focus or hover and a label for screen readers; contrast meets WCAG AA; nothing relies on color alone, so
  flagged anomalies also carry a mark.
- **`web/package.json` defines `typecheck`, `test` and `build`.** `cargo xtask check` runs them (after `npm ci`)
  as soon as `web/package.json` exists, and CI runs them on macOS, Windows and Linux. Use `"test": "node --test"`
  or similar; a script that always passes is worse than none.
- **Design tokens** (color, type, spacing) live in one CSS file owned by the design owner; code uses tokens,
  never literal colors.
- Offline: a service worker caches the app shell and the tiles of pinned regions. It is tested with the
  network off.
- Test: one smoke test that loads the app, applies a fixed area against fixture tiles, and checks the calendar
  cells.

## Git

- A branch per task, named `<owner>/<task>`. Small PRs merged within hours. Rebase when older than two hours.
- Pull requests are squashed, so **the PR title and description are the commit**: title imperative, capitalized, at
  most 72 characters, no final period; the description follows the template and **Why** gives the reason, not
  the change. One idea per pull request. No tool attribution. Your own commits inside the branch are scratch
  and never reach `main`, but keep them honest.
- Never commit data, keys, `target/`, `node_modules/`, `tiles/`.
- A change to a contract (`firecal-types`, tile or aggregate format, `firecal.d.ts`) is its **own PR**, with the
  docs and every consumer updated, and the lead reviews it.

## Briefing an agent

A vague brief produces vague code. Every task given to Claude Code or Codex has these five parts:

```
Read AGENTS.md and docs/style.md.
Crate or package: <the one directory you may edit>
Contract: <the types or file format you implement or consume, with the path>
Task: <one thing, in a sentence>
Done when: <the test that must pass, and the command that runs it>
Do not touch: everything outside the directory above. If a contract looks wrong, stop and say so.
```

The agent builds and runs what it wrote, looks at the result, and the PR says what it ran and what it could
not.
